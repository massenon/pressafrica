# Africa Global Press: technical documentation

Status: HTML prototype (static, mock back-office) ready to be ported to the target Laravel stack. Updated 2026-10-26.

## 1. Two layers

| Layer | What it is today | Target in production |
|---|---|---|
| Prototype | Static HTML + Tailwind 3.4 + vanilla JS in `prototype_html/`, generated by Python (`tools/`). Back-office is a mock on `localStorage`. | Visual and UX reference, source of the design tokens and of the content model |
| Application | Not started | Laravel 12.70 / PHP 8.3, MySQL, see section 8 |

The prototype keeps 100 % of the Foxiz template layout (pressafrica.media). No redesign was done.

## 3. Build and check

Run from `prototype_html` for CSS, from `tools` for the site.

```
npx tailwindcss -c tailwind.config.js -i assets/css/src.css -o assets/css/app.min.css --minify
npx tailwindcss -c tailwind.config.js -i assets/css/admin.src.css -o assets/css/admin.min.css --minify
python build_site.py     # generates fr/ and en/, sitemap, manifest
python site_check.py     # expect: OK: no problems (171 pages, 26,436 links)
```

Inside Tailwind `theme()`, write `colors.alert` and `colors.brand.DEFAULT`. A failed CSS build leaves the old CSS in place silently, so read the output.
Open `prototype_html/index.html` by double-click (no server needed). The service worker only registers over http(s); after changes, unregister it and clear `caches` to see fresh files.

## 4. Design tokens (customisation)

Defined as CSS variables in `src.css` (public) and `admin.src.css` (admin), light and dark:
brand `#013079`, flash `#ffec00`, alert `#e02200`, `--c-link`, `--c-line`, `--c-meta`, `--c-surface*`, `--gap:24px`, `--r`, `--r-card`.
Change a token once; every component follows. Do not hard-code hex values in components.

## 5. Public site

- Page types: home, category archives, thematic landings, article, podcasts, contact, search.
- Home: hero, latest, "Les plus lus" (4 items), topic blocks (Société, Politique, Culture), newsletter.
- Article: two panels (main column and sticky 300 px sidebar at >= 1024 px). Sidebar: Follow us (Facebook, X, Pinterest, Instagram), Must read, newsletter. Left share rail on desktop, reading-progress bar.
- Social icons live in the SVG sprite in `build_site.py` (`i-facebook`, `i-x`, `i-pinterest`, `i-instagram`). Use solid fills only: gradients inside a hidden sprite do not render in Chromium. In the navy list each icon sits on a white badge, so `currentColor` icons (X) are forced to black.
- SEO: unique title and description per page (`SEO_TITLES`, `DESCRIPTIONS`), canonical, hreflang FR/EN, Open Graph, JSON-LD (NewsArticle, BreadcrumbList, PodcastSeries/PodcastEpisode), sitemap.
- Accessibility: WCAG 2.2 AA target, skip link, visible focus, labelled landmarks, reduced-motion respected. Checked with axe (0 violations on audited pages).
- "Explore by topic" popup (Foxiz template popup, top position): `topics_popup()` in `build_site.py` writes `<template id="tmpl-topics-popup">` (8 topic columns with the latest articles, plus a channels strip); `app.js` `topicsPopup()` clones it into a `.popup-host` dialog on first click and reuses `openDialog/closeDialog` (Esc, focus trap, inert page, scroll lock, focus return, click outside). CSS block "Topics popup" in `src.css`. Visible from 1024 px; the burger keeps opening the off-canvas menu on mobile.
- Navigation: Hotwire Turbo Drive (`assets/js/vendor/turbo.min.js`, 8.0.23 minified with esbuild, 25.7 kB gzip) swaps the page body, with prefetch on hover; the FR/EN article switch uses the same path. `app.js` is re-executed after each swap and first removes its document/window listeners and intervals (`__agpOff`). It needs http(s): over `file://` the fetch fails and Turbo falls back to a normal page load, so serve the folder (`python -m http.server`) to see it.
- Performance: responsive images with `srcset`, lazy loading, minified CSS, no framework JS besides Turbo. Enable gzip or brotli at deployment.

## 6. Podcasts module

Data: `data/podcasts.json` = `shows[]` and `episodes[]`.

```
episode: id, show, article (FR article id, optional), date, duration (seconds),
         audio ("assets/audio/ep-001-{lang}.mp3", {lang} is replaced by fr or en),
         status (published | draft), fr{title,desc}, en{title,desc}
```

- Public: `podcasts_body()` builds the page (latest episode with player, show filter, list, shows, newsletter). The player is a native `<audio preload="none">`. The menu panel lists the 4 latest episodes. JSON-LD is emitted by `podcasts_jsonld()`.
- Admin: `admin/podcasts.html` + `assets/js/admin-podcasts.js`. Episodes table (search, sort, status filter, bulk publish), create/edit form (FR and EN text), shows card, listen preview, "Export JSON". Data in `localStorage` key `podcasts`, seeded from `admin/podcasts-seed.js`.
- Publish flow (mock): Export JSON, replace `data/podcasts.json`, copy it to `admin/podcasts-seed.js` (same content as `window.AGP_PODCASTS = ...`), run `build_site.py`.
- Audio: the current MP3 files are synthetic-voice summaries (about 25 s) made with `tools/make_podcast_audio.ps1` (Windows voices Hortense FR, Zira EN, ffmpeg). They are placeholders for real recordings. To replace one, drop an MP3 with the same file name and set the real `duration`.

## 7. Back-office prototype

- Framework in `admin-lib.js` / `admin.js`: `AGP.page`, `AGP.table`, `AGP.formModal`, `AGP.modal`, `AGP.confirm`, `AGP.toast`, `AGP.store`, `AGP.can(module, action)`.
- Navigation is the `NAV` array in `admin.js`; modules in `MODULES`; page-to-module in `PAGE_MOD`. `migrate()` adds new permissions to roles already stored in the browser.
- Roles and permissions live in `localStorage` (`roles`). Demo login is on `admin/login.html`.
- Strict CSP on admin pages: `script-src 'self'`, `connect-src 'none'`. Put page scripts in files, never inline.
- Add a module: create `admin-<name>.js` with `AGP.page('<name>', fn)`, copy an existing `admin/<page>.html`, then register it in `NAV`, `MODULES`, `PAGE_MOD`.

## 8. Target production stack (decided, not yet built)

| Area | Choice |
|---|---|
| Backend | Laravel 12.70, PHP 8.3, MySQL |
| Auth | Sanctum 4 (tokens and sessions) |
| Roles and permissions | spatie/laravel-permission 8 (maps to the prototype `roles` and `AGP.can`) |
| HTML sanitising | mews/purifier (article bodies, comments) |
| Administration | Livewire 3.6 with Tailwind (owner decision 2026-10-28), SweetAlert2, Chart.js, Quill, Choices, flatpickr |
| Public front end | Vue 3, Inertia 2, Pinia, vue-i18n, Ziggy, TypeScript. No server-side rendering |

Points to decide before coding:
1. **SEO without SSR.** Inertia without SSR serves an empty shell to crawlers that do not run JavaScript. For a news site this hurts indexing and Lighthouse. Options: enable Inertia SSR, or serve article and category pages as Blade with Vue islands. This conflicts with the "no SSR" constraint and needs a decision.
2. **Admin styling.** The prototype admin uses Tailwind tokens; the target admin uses Bootstrap. Port the tokens as Bootstrap CSS variables so the look stays the same.
3. **Permissions.** Keep the module/action names from `MODULES` as spatie permission names (`posts.create`, `podcasts.publish`, ...).

Suggested data model (from the prototype): users, roles, permissions, categories, posts and post_translations (fr/en), media, comments, ads, podcast_shows, podcast_episodes (with `audio_path` per language), newsletter_subscribers, settings, audit_log.
